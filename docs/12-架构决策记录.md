# 阅集图书商城架构决策记录

版本：1.0｜以下为设计阶段决策，验证状态均为待实现验证。

每条包含背景、候选、决定、代价和复审条件。已被实现使用的决定改变时追加新记录，不能删除旧理由。用户已确定多商家图书、Java/Vue、Markdown、支付宝沙箱加模拟、Windows 加 Linux 单机；其他为与其一致的设计默认。

## ADR-01 领域与首版范围

背景：实验需要完整交易及商家结算，同时避免复杂品类规则稀释核心。候选：社区超市、综合商城、图书商城。决定：多商家实体新书，公共 ISBN 资料与店铺商品分离，首版单 Product 单 SKU、包邮、不含促销。代价：不能表现多规格服装、生鲜保质期或优惠分摊。复审：明确新增品类或营销需求时重新定义快照、金额、售后和测试。

## ADR-02 模块化单体

背景：单机、小团队、课程周期，订单库存需要可靠事务。候选：模块化单体、微服务。决定：单体按业务域分模块，本地调用与统一数据库事务，前端独立。代价：无法独立扩缩各业务模块，数据库资源共享。复审：业务规模或组织边界确实要求独立部署，并已有性能证据，而不是因为“企业级”字样。

## ADR-03 Java 与 Vue

背景：用户选择沿用 Java/Vue，现有设计偏 Spring 生态。候选：Java/Vue、Python/Vue、TypeScript 全栈。决定：Java 21、Spring Boot 3.5、Spring Security、MyBatis-Plus；Vue 3/TypeScript、Pinia、Element Plus。代价：双语言工程及版本兼容维护。复审：官方支持周期或依赖冲突需要升级时，先验证 BOM、数据库迁移和契约，不静默迁移到新大版本。

## ADR-04 关系数据库与模型

背景：库存、退款与结算需要事务、唯一约束和可审计查询。候选：MySQL、PostgreSQL、纯文档数据库。决定：MySQL 8.4 InnoDB、显式字段与外键、Flyway；金额 DECIMAL，接口金额字符串，历史信息快照。代价：JSON 不能替代关系建模，模糊搜索规模有限。复审：明确的检索性能瓶颈或特定数据库能力需求时再评估替代。

## ADR-05 Redis 的边界

背景：公开读可缓存、登录和限流需要共享状态。候选：纯数据库、Redis、以 Redis 为库存主账。决定：Redis 做短期缓存、限流和会话辅助；核心库存、幂等与资金事实在 MySQL。代价：缓存有短暂滞后，增加一个服务；故障时需受控降级。复审：热点和缓存命中数据证明现策略不够，而不是先把交易状态全搬到 Redis。

## ADR-06 RabbitMQ 与 Outbox

背景：交易提交后通知及异步处理不能丢失，同时需允许中间件故障。候选：事务后直接发消息、Outbox＋RabbitMQ、Kafka、引入 Saga/TCC。决定：本地事务写 Outbox，发布确认，至少一次投递，消费者去重。代价：存在消息延迟和重复，需后台扫描、死信与重放。复审：跨服务交易或大规模事件流出现时再选择 Saga/Kafka；首版无需 TCC。

## ADR-07 JWT 与会话撤销

背景：独立前端需统一鉴权，也要支持退出/禁用快速生效。候选：纯服务器 Session、自建 OAuth2、JWT＋轮换刷新会话。决定：JWT 访问＋数据库可撤销刷新族、RBAC 与资源归属联合校验；BCrypt；刷新 Cookie 配 CSRF。代价：额外会话状态，不能宣传 JWT 完全无状态；前端安全与令牌轮换需专门测试。复审：接入机构 SSO 时采用外部 OIDC/OAuth2 身份提供方。

## ADR-08 拆单支付和沙箱边界

背景：跨店购买需要清楚的履约与结算边界，用户选择真实沙箱加模拟。候选：合并支付、多店独立付款。决定：提交同事务拆单，每店独立支付；支付宝沙箱正式联调，LOCAL_MOCK 仅开发测试；每订单唯一渠道交易号。代价：会员多店购物需多次支付；不覆盖平台真实分账。复审：真正接入商业多商户支付时重新设计合单、分账、手续费和监管边界。

## ADR-09 库存预占和售后回补

背景：支付有异步和超时，单纯付款时扣库存容易失败或超卖。候选：下单即实扣、下单预占、纯 Redis 预减。决定：MySQL 下单预占，支付成功扣实物，核实关单释放；未发货退款成功回补，退货验收可再售时回补。代价：渠道未知会延长库存冻结，必须告警查单；恢复规则更多。复审：高峰下锁竞争经测试成为瓶颈时再优化，不能破坏账实不变量。

## ADR-10 单机容器部署与 CI CD

背景：用户选定 Windows 开发和单台 Linux。候选：本地-only、Compose 单机、Kubernetes。决定：Docker Compose、Nginx，GitHub Actions 与 GHCR 制品，SSH 发布；维护窗口发布，兼容迁移及上一 digest 回滚。代价：单点、维护停机、磁盘容量和备份需管理；不声称零停机。复审：容量或可用性目标超出单机能力时采用多实例和外部数据服务。

## ADR-11 可观测性与文件存储

背景：需能证明故障定位和恢复，预算有限。候选：最小日志、Prometheus/Grafana/Loki、本期引入完整追踪/对象存储。决定：指标＋结构化日志及 traceId，私有文件由后端鉴权，本地持久卷与备份；不引入 CDN 和分布式追踪平台。代价：监控占资源，本地文件扩容受单机限制。复审：文件规模或跨实例访问需求增加时评估对象存储；调用跨服务后再引入链路追踪。

## ADR-12 模拟结算与范围控制

背景：实验要求结算闭环，真实商户分账超出本期账号与业务范围。候选：忽略结算、只统计收入、账单审核＋模拟出款。决定：完整可追溯结算账本、3% 手续费、售后窗口后结算、独立审核、模拟出款及差异调整。代价：不能当真实银行/商家资金结算系统使用。复审：接入真实出款时必须重新设计账户、渠道对账、权限及补偿，不只替换一个 HTTP URL。

## 决策维护规范

### ADR-13 阶段 A 工程占位与依赖隔离

日期：2026-10-23；状态：已接受，授权来源为用户明确要求实施阶段 A。决定：保留 11 个业务包的 Controller/Service/Repository 边界，但不添加虚构业务类；阶段 A 不接 MySQL/Redis/RabbitMQ，不提前编写迁移。92 项操作以单一 OpenAPI 清单建立失败关闭门禁，未实现返回 501，模拟确认不注册；增加技术错误 NOT_IMPLEMENTED 和 METHOD_NOT_ALLOWED。业务接口安全与参数验证留给对应实现阶段，不能把占位测试计入完整业务验收。

采用项目内隔离 Java 21/Node 24/Maven，精确版本及官方镜像 digest 先冻结，再生成依赖锁；Docker 无守护进程时仅核实 registry 元数据，容器运行明确未验证。代价：本阶段健康检查不能证明数据库或交易就绪；后续开放路由时必须同步门禁、安全、契约与测试。所有金额/ID 的网络表达与原设计保持一致，无范围扩展。

### ADR-14 阶段 B 会话、迁移与隔离验证

日期：2026-10-23；状态：已接受，依据用户明确授权的阶段 B 范围。影响 FR-01/12、FR-04 地址，API-01—10/70—77/84—88 及其 10 张支撑表，不改变业务政策或网络字段。

选择 Spring Security BOM 管理的 Nimbus HS256 编解码，避免重复引入 JWT 库；刷新令牌哈希持久化并保留旧行，按用户→会话的固定顺序加锁。重放撤销通过明确不回滚的会话拒绝异常提交，7 天是首次登录的绝对上限。管理员变更复用既有 ADMIN 角色行串行化，事务内复核权限并保护最后管理员，不新增锁表或分布式服务。代价是每次 Bearer 校验查询数据库，授权变更串行化；当前单机规模优先保证撤销和隔离。

Flyway V1—V4 只增加结构/目录/审计触发器；默认地址按 03 已规定的生成值唯一约束实施。Flyway 固定 11.20.3，以实际 MySQL 8.4.13 验证代替继续忽略旧驱动的兼容提示。Docker daemon 不可用，使用官方校验的项目内隔离 MySQL 原生进程运行真实事务/迁移测试，没有 H2 替代；容器与 Linux 验证留待部署阶段。开发账号和空库生产管理员初始化相互隔离，口令不进入迁移，生产首次初始化仅从显式安全环境输入。

验证空库/重复/前滚兼容、CSRF/重放、当前授权、横向资源范围、并发最后管理员保护和种子幂等；结果以 B 交接及机器证据为准。复审触发器：迁移生产数据库、改为多实例、签名密钥轮换或性能不足时，重新评估迁移权限、限流/密钥方案和查询代价，不能省略会话撤销。

### ADR-15 阶段 C 商品库存和安全文件

日期：2026-10-23；状态：已接受，授权为用户阶段 C 任务。影响 FR-02—04/13、API-11—25/63—68/90/92；业务字段与既定政策保持不变。

选择 MySQL 真实事务与唯一/CHECK/FK 约束、一 Product 一 SKU、库存独立版本及只增减实物量的调整服务；幂等与原始响应快照同事务持久化，缓存不参与写依据。分类/书目/商品元数据修改沿用已有授权行串行锁，避免分类关系与状态并发竞态；库存以用户和 SKU 行锁控制，不因目录全局锁而合并库存主账。代价是目录写吞吐有限，须以性能证据决定优化，不能删除鉴权和版本检查。

为库存流水 FK、售后凭证关联鉴权和真实公开评价查询，按 03 建立必要的完整空订单/售后/评价依赖结构；不采用去掉外键或虚构关联数据的方案，不开放相关业务写接口。后续 D/F 在既有结构上追加迁移和服务。V1—V4 不改写。

文件用 JDK ImageIO + 固定版本 TwelveMonkeys WebP 解码器，格式与扩展/MIME一致验证、5MB及像素限制、统一重编码 PNG；public/private 分目录、私有下载每次鉴权，生产不暴露整个存储根。未接 Redis 时直接查询数据库，不伪造缓存故障或性能结论。开发种子先验收再经正式 API 生成目录/库存/购物车，不生成评价/交易数据；脚本遵守限流，重复运行只核验。

验证由真实 MySQL HTTP、并发同键、版本、预占保护、流水只追加和文件越权用例完成，结果以 C 证据为准。复审触发器：多实例、目录写锁瓶颈、文件格式/容量扩展或上线 Linux/Nginx 时，重新评估共享限流、缓存及资源映射，不能把展示缓存作为库存事实。

新增记录应包含编号、日期、状态、背景、候选与比较、决定、代价、影响的需求/接口/表、验证方案及复审触发器。状态为拟议、已接受、已替代；本版“已接受”只表示设计基线，不表示技术部署或效果已经验证。拒绝方案保留关键理由即可，不罗列无关工具。

### ADR-16 阶段 D 本地原子下单与真实关闭意图

日期：2026-10-24；状态：已接受，授权为用户阶段 D 实施任务。影响 FR-05/07、API-26—31、预览/订单及 V7 四张支撑表；不更改状态机、持久化业务字段或金额/ID 网络表达。

沿用现有 ADMIN 授权锚点行：目录、店铺和授权写持排他锁，交易持共享锁；不同会员可并发下单，避免核验后同时下架或变价。交易依次共享锚点、锁本人、锁预览、按数值 SKU ID 升序锁全部库存，再按 shopId 建单。后续对既有订单的资金操作仍须遵循订单→订单行→升序库存→预占→财务明细。代价是长时间目录写会影响结算受理，需要以实际性能证据评估，不能提前移除保护。

选择 READ_COMMITTED 的新事务与最多两次锁冲突重试；库存条件更新、预占、只追加流水、按店订单/行/状态日志、购物车消费、Outbox、预览使用标记及幂等响应一起提交。幂等先于过期检查进行，丢失响应可重放原键；不同键使用已用预览按 04 返回 STATE_CONFLICT。SQL 故障回滚全批，而非补偿式逐店建单。无需分布式事务或 Redis 全局锁。

取消和到期扫描只推进 PENDING_PAYMENT→CLOSING；数据库租约保护扫描，多实例按订单锁复核。不凭通知缺失或 reservation 过期释放库存。支付渠道、关闭确认、未知状态重试告警由 E 完成。Outbox 本阶段持久化真实 OrderCreated 信封为 PENDING；没有 Broker 确认不记已发布，不伪造 OrderPaid/OrderClosed。后续发布者与消费者必须按 02 实现确认、租约、重试及去重。

验收使用真实 MySQL HTTP、100 个独立会员同时争抢最后 10 本、20 次重放及并发重放、第二店 Outbox 故障回滚，以及真实数据库死锁后的新事务重试。证据见 D 交接。上线、多实例或锁争用达到性能瓶颈时复审；当前不宣称完成渠道收敛、RabbitMQ 发布消费或 Linux 部署。

### ADR-17 迟到付款补偿原因字段容量修正

日期：2026-10-25；状态：已接受，用户明确同意“扩为 VARCHAR(32) 并记录”。影响 FR-07、TC-12、03 第 7 节 refund.reason_type 及 V8 支付退款结构；不改变允许值、接口、金额表达、退款唯一约束或 02 状态机。

隔离 MySQL 首轮集成验证显示 `LATE_PAYMENT_COMPENSATION` 长 25 字符，无法写入既定 `VARCHAR(24)`。决定仅将字段容量扩至 `VARCHAR(32)`，文档按既有 `ENUM(n)` 记法同步为 `ENUM(32)`，以追加 V9 前滚迁移实现，保留 V1—V8 文件及所有既有值。没有截断枚举，也未放宽 CHECK。

代价是字段及唯一索引表达式上限增至 32 字符。验证方案为 MySQL 空库前滚、从 V1 带旧数据升级、迟到支付退款实际插入及重复处理后不重新占库存；证据见 E 交接。复审触发器：新增退款原因超过 32 字符或改变退款唯一性时重新决策。

### ADR-18 收尾阶段按既定设计补齐基础设施与契约

日期：2026-10-26；状态：已接受，授权来自剩余任务计划 R02—R12。沿用 02 的数据库事实、事务外渠道/消息调用与租约规则，按 03 追加 V11 consumed_event 表；不修改已有迁移。RabbitMQ 发布确认后记发布成功，消费者在去重和审计事务提交后确认，失败经有界重试进入死信，管理员必须提交原事件 ID 和原因才可重放。消费仅观察已提交事实，不重复操作业务库存和账务。

Redis 仅缓存分类及短期商品展示并辅助限流；库存、权限、撤销和刷新轮换仍由数据库决定。展示故障有界回源，高风险写及刷新在 Redis 故障时返回明确依赖错误。提交后递增缓存版本，失效重试按代次确认，避免并发失效被旧请求清除。代价是依赖故障会限制部分操作，必须通过真实连接故障与恢复测试验证。

严格响应校验发现阶段 F 生成器将 04 标为可选、列表省略和商家屏蔽的结算字段列为必填。按原设计修正生成器，并补齐 AdjustmentView 原设计已要求的 originalSettlementId/orderId/issueId；不增加新业务字段、接口或改变金额与 ID 类型。原财务及业务断言继续保留。

容器构建发现阶段 I Nginx digest 抄录错误，恢复为阶段 A 已冻结且实际拉取成功的 digest；历史 I 记录保留，实际版本记入收尾冻结记录。CI 的 Maven 命令在 backend 目录执行，避免相对 settings 路径失效。统一控制测试中的后台调度，仅隔离自动执行，不跳过直接调用恢复服务的测试。

复审触发器：引入多实例业务消费、真实渠道能力、远端部署或更改状态机时重新核对锁顺序、权限与运维证据。实际结果见收尾交接和原始日志，不由本 ADR 宣称验收通过。

### ADR-19 保留本地演示技术基线并接受未修复安全风险

日期：2026-10-26；状态：已接受。用户先批准另行规划 Boot 4 / Spring 7，随后明确撤销：“不实现兼容升级 目前就很好了 安全问题可以忽略 我不会上线的”。以该最新决策为准，未执行 Boot 4 / Spring 7 升级，保留 Java 21、Boot 3.5.16、Spring 6.2.19 及现有 BOM。

取消为安全升级提出的 Jackson、Netty、RabbitMQ 客户端覆盖版本，停止对应候选版本复测；保留取消前日志，但不将其计为最终基线验证。既有完整 clean verify 的 178 项、1173/1463 服务分支覆盖率与恢复证据仍关联其实际基线。

实际后端镜像扫描有 17 条 HIGH/CRITICAL 发现，用户接受本地非生产用途下暂不修复。此项状态是风险已接受，不是扫描通过、漏洞已消除或已达到发布门禁。原始扫描结果继续保存，不增加忽略条目、不放宽 CI 扫描阈值，不申请或执行生产发布。若未来改为对外部署，须重新决策和验证依赖安全基线。
