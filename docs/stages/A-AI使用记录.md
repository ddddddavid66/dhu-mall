## 1 任务及原始提示词

用户要求按项目 AGENTS.md 执行阶段 A，原文核心内容如下：

> 前置：设计基线已接受，尚无业务实现。
>
> 阅读 01、02、04、06、08 和 12。只完成前后端独立工程、后端模块分层、统一 Result/异常/分页/traceId、配置隔离、测试骨架和 OpenAPI 契约骨架。先核对并冻结兼容补丁版本和镜像 digest，再生成锁文件。不得借初始化加入微服务、额外数据库、优惠券或其他业务。为 04 的所有操作建立契约清单，未实现接口明确标记，不返回虚假业务成功。验证依赖安装、编译、类型检查、基础测试和健康接口，提交版本冻结及交接记录。
>
> 完成标准：工具链记录可核实，空工程可构建；公共错误、分页和 ID/金额类型定义唯一；无真实密钥。此阶段不要求购物闭环完成。

输入材料：AGENTS.md、docs/README.md、01—08、12，以及已有设计阶段对话。使用 code_skill 规范；使用 agent-reach 的 Exa 搜索取得官方兼容性资料，再通过官方 Maven Central/npm/Adoptium/Node/Docker Hub 元数据核实精确版本。

## 3 修正与验证过程

- 官方 Docker Registry 鉴权域名请求超时，改用 Docker Hub 官方 library 标签 API 查询摘要，没有读取本机 Docker 凭据，也没有编造 digest。
- 首次 Wrapper 生成时 PowerShell 对未引号包裹的 Maven 参数解析出错；改为完整字符串参数后生成成功，失败日志与成功结果均保留在本地证据中。
- 生成契约时发现 Windows Python 默认 GBK 读源文件失败，显式指定 UTF-8 并重新生成，未修改设计中的中文字段或接口编号。
- 首轮后端测试发现 CORS 配置未以 Spring Security 识别的名称接入；修正 bean 名称，并用原始 HTTP 客户端确保 Origin 预检头实际发送。没有放宽来源白名单，修复后允许源通过、非法源仍拒绝。
- 冒烟工具最初把代理后的响应头名称当大小写敏感键处理；按 HTTP 规范改为大小写不敏感比较，实际 501 与 traceId 保持一致。
- 最终执行 scripts/verify.ps1，全部检查通过；另执行打包 JAR 和 Vite 代理的 8 项无副作用冒烟。具体命令、结果和证据见 A-验证与交接.md。

“人工修改”字段：本轮没有可确认的人类代码修改，只有 AI 根据真实运行错误修正代码；项目负责人尚待审阅。不能将 AI 自修正冒充人为审查。
