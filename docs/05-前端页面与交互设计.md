# 阅集图书商城前端页面与交互设计

版本：1.0｜技术基线：Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus。

## 1 信息架构和视觉方向

一个独立前端工程，分会员商城布局和管理工作台布局。会员入口为 `/`，工作台为 `/workbench`；URL 路由不是权限边界，数据由后端鉴权。路由参数中的 ID 和接口 ID 同义。

风格为清晰、安静的书店阅读体验：浅米白背景、深色正文、墨绿色主按钮；价格和异常使用语义色而非全部高饱和。字体优先系统中文字体，正文 14—16px，正文行高不低于 1.5。封面统一 3:4 比例，保持原图不拉伸。页面不摆放“Controller、Redis、JWT”等开发说明。

设计标记：桌面内容最大宽度 1200px，24px 区块间距；移动端 16px 边距；小于 768px 使用移动布局，768—1023px 为平板，1024px 以上为桌面。后台建议最小 1280px，较窄屏表格允许横向滚动，不把所有列挤成不可读文字。

## 2 共享布局线框

以下为结构示意，不是可执行页面代码。

### 2.1 商城首页与列表

| 自上而下区域 | 桌面布局 | 移动布局 |
|---|---|---|
| 顶栏 | 品牌、搜索输入、购物车数量、账户入口 | 品牌与账户一行，搜索独占下一行 |
| 导航 | 分类横排、精选入口 | 可横滑分类 |
| 内容区 | 列表左侧 200px 筛选，右侧排序与 4 列商品卡 | 筛选抽屉、排序栏、2 列商品卡 |
| 商品卡 | 封面、两行书名、作者、店铺、价格、缺货标签 | 保持相同关键信息，不依赖悬停 |
| 底部 | 分页、项目信息与沙箱演示标识 | 加大分页触控区，不使用无限滚动隐藏定位 |

首页使用精选图书网格和分类入口，不做无数据的轮播广告。搜索页显示关键词、结果总数和清空筛选；没有结果时提供重置按钮，不填充与关键词无关假数据。

### 2.2 商品详情

桌面从左到右为封面 35%、书名作者出版社与店铺报价 40%、购买区 25%；下方依次为图书说明、出版信息和评价。移动端纵向排列，底部固定数量和加购按钮。缺货、下架、请求失败分别显示，不把异常统一当成“已售罄”。

### 2.3 管理工作台

左侧 220px 导航、顶部 56px 用户与店铺切换、主区面包屑和标题。常规页面采用“筛选栏 → 操作栏 → 表格 → 分页”；复杂编辑使用独立页面，简短查看用右侧抽屉。退款和结算确认对话框展示单号、金额和对象，不能只问“确定吗”。

## 3 会员页面设计

| 页面编号与路由 | 内容和交互 | 对接接口与边界 |
|---|---|---|
| UI-01 `/` | 精选网格、分类、搜索、登录和购物车入口 | API-11/12；不展示管理员功能 |
| UI-02 `/search` | 关键词、分类、店铺、排序、分页；条件与页码进入 URL，返回时恢复 | API-12；输入防抖 300ms，取消旧请求，最新请求结果才能覆盖页面 |
| UI-03 `/products/:id` | 封面、图书资料、商家价格库存、数量、加购、立即购买、评价 | API-13/14/24；立即购买先设置购物车，再跳结算；SKU 首版唯一，不造规格选择器 |
| UI-04 `/login` 与 `/register` | 清晰标签、密码可见切换、格式和错误说明、回到原页面 | API-01/02；只允许站内回跳；注册成功进入登录，不伪装为已建立会话 |
| UI-05 `/cart` | 按店铺分组、商品勾选、数量、单项删除、分店小计和总计 | API-23/24/25；数量用绝对值提交；服务器确认后刷新小计；缺货项不可勾选 |
| UI-06 `/checkout` | 地址卡、店铺分组商品、包邮说明、每店金额、总额、提交 | API-07/26/27；只用后端金额；价格变化高亮差额并要求重新预览 |
| UI-07 `/checkout/batches/:id` | 提交成功后列各店订单，每个单独“去支付”；说明互不影响 | API-28/32；不显示虚假的“一键合并付款” |
| UI-08 `/payments/:id` | 金额、沙箱标识、渠道入口、支付状态、返回订单 | API-33/34；模拟按钮仅 LOCAL_MOCK 可见且后端路由受限；跳回后查后端状态 |
| UI-09 `/account/orders` | 状态标签页、订单号、店铺、商品摘要、金额及操作 | API-29；筛选持久在 URL；分页不提前混合多个状态结果 |
| UI-10 `/account/orders/:id` | 订单/财务双状态、地址快照、明细、时间线、物流；按状态显示支付、取消、收货、售后和评价 | API-30/31/32/36；取消可能显示“关闭处理中”，不能乐观显示已取消 |
| UI-11 `/account/addresses` | 地址列表、新建编辑、默认切换、删除确认 | API-07—10；最多 20 个；编辑不影响既有订单快照 |
| UI-12 `/account/after-sales/new` | 选择可售后订单行、类型、数量、原因、上传凭证、预计退款金额 | API-30/21/42；预计金额按快照显示，最终以服务端核对为准；不可输入任意退款金额 |
| UI-13 `/account/after-sales` 与 `/:id` | 列表和进度、审核原因、退货截止、退货运单、退款状态 | API-43—46；仅 REQUESTED 可撤销；退款失败显示“待处理”而非完成 |
| UI-14 `/account/reviews/new` | 指定订单行、1—5 星、评价文本、提交后只读 | API-30/37；全退、超时、已评价时阻止提交并解释 |
| UI-15 `/account/security` | 修改密码、当前身份、退出 | API-05/06/04；改密后重新登录，不在页面回显旧密码 |

支付状态轮询前 60 秒每 3 秒一次，之后每 10 秒一次，最多 5 分钟后停下并提供手动刷新；页面隐藏时暂停，恢复时立即查询一次。轮询不能触发新的付款。只有本地持久状态 SUCCEEDED 才显示成功；渠道回跳 query 不能作为证据。

首版后台不提供批量退款、批量出款、任意状态编辑或全量个人信息导出。列表失败时保留筛选条件，明确重试，不用旧数据冒充最新成功结果。

## 5 前端工程设计

组件层次：App → StorefrontLayout / WorkbenchLayout → RoutePage → 业务组件 → 基础组件。通用组件包括 BookCard、MoneyText、StatusBadge、PagedTable、AddressEditor、OrderTimeline、ConfirmAction、FileUploader、AsyncState。会员商品卡使用自定义布局，后台表单和表格复用 Element Plus。

状态分工：Pinia 保存当前身份、权限、店铺上下文和购物车摘要；页面局部状态保存筛选、弹窗和表单草稿；URL 保存可分享的搜索及列表条件；服务端是价格、库存、订单和权限最终来源。访问令牌只放内存，页面刷新通过 Cookie 刷新接口恢复会话，不将令牌放 localStorage。

API 层集中实现 Result 解析、字段类型、traceId 记录和 401 刷新。并发 401 合并成一次刷新，其他请求等待；每请求最多自动重试一次，刷新失败统一退出。403 展示无权限，404 不泄露资源是否属于别人，409 根据 code 展示具体恢复路径。

关键提交开始时生成并保留 K；超时后先用同键重试或查询原业务结果，不能立刻新建键。成功完成或用户明确开始新的业务动作后才创建新键。退款必须先查询确认 FAILED，再以新 K 发起对原 refundId 的执行；仍在 PROCESSING 时只查询，不建新退款。按钮禁用、防抖是体验措施，不能替代服务端幂等。切换店铺时取消旧店请求并清空店铺缓存，防止旧响应覆盖新店页面。

文件上传后只保存 fileId，私有凭证通过鉴权下载获取临时 Blob URL，离开页面释放；不要把 Bearer token 拼在图片 URL。富文本首版不支持，所有书评和描述以纯文本渲染。

## 6 交互状态和无障碍验收

| 状态 | 统一行为 |
|---|---|
| 首次加载 | 商品用占位骨架，表格有加载说明，避免空白闪烁 |
| 无数据 | 解释当前没有什么，给出有效下一步，不显示虚假样本 |
| 网络或服务失败 | 保留用户输入，显示重试和 traceId 复制；密码字段不持久保存 |
| 处理中 | 支付、退款、关闭订单显示真实处理中状态，可查询，不能假成功 |
| 版本冲突 | 展示“内容已被更新”，重新获取并由用户确认再提交 |
| 无权限 | 独立页面或行内说明；只显示允许的返回入口 |
| 表单不合法 | 错误紧邻字段，焦点移至首个错误，不能仅用红色边框 |

所有交互可用键盘到达；表单标签与控件关联；弹窗包含焦点管理；按钮触控区域至少 44px；颜色不是唯一状态提示；图片有替代文本；表格金额右对齐、日期统一。低分辨率、长书名、无封面、多个店铺及中文长错误都纳入页面测试。

验收以页面操作真正引发正确接口和后端结果为准。静态页面、固定 mock 成功提示或只隐藏按钮均不能替代实际联调证据。
