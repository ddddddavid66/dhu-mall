# 阅集图书商城测试与验收设计

版本：1.0｜状态：测试计划，所有运行结果均待实施验证。

## 1 测试分层与门禁

| 层级 | 工具方向 | 范围与通过标准 |
|---|---|---|
| 单元 | JUnit 5、Vitest | 金额、时间窗口、状态迁移、权限和表单规则；核心服务分支覆盖≥80%，不能仅靠 DTO 覆盖凑比例 |
| 集成 | Testcontainers、Spring 测试体系 | 使用真实 MySQL/Redis/RabbitMQ 验证事务、唯一约束、锁、消息；不能用 H2 替代并发库存测试 |
| 契约 | OpenAPI 校验与 HTTP 测试 | API-01—API-92 每项有合法和不合法输入检查；认证、分页、字段类型和错误码符合 04 |
| 浏览器 E2E | Playwright | 会员购买、后台履约、退款与结算、跨角色隔离；截图和 trace 留存 |
| 安全 | 依赖/密钥扫描与专门权限用例 | 匿名、水平/垂直越权、注入、XSS、CSRF、上传、令牌撤销，无未处理高危问题 |
| 性能 | k6 | 按 01 NFR-01 固定硬件、数据集、预热和负载记录 P50/P95/P99、RPS、错误率及资源指标 |
| 恢复 | 隔离环境演练 | MQ/Redis/数据库故障、进程重启、备份恢复、上一版镜像回滚可复现 |

合并门禁运行静态检查、单元、集成、契约及最小 E2E；定时/发布前运行完整 E2E、性能和恢复演练。涉及钱和库存的失败不得被重试机制“掩盖成通过”；第一次失败、重试和根因均记录。

## 2 固定测试数据

种子包含店铺 A/B/C、会员甲/乙、独立商家仓库及客服财务；同一本 ISBN 在 A/B 均销售；普通库存 100、抢购库存 10、缺货库存 0；下架商品、停业店铺；处于各订单和售后状态的样本。使用独立 test 库，测试执行后通过运行编号清理自己创建的数据，不能清空共享开发环境。

金额样本包括 19.90×3、退款 1 本、平台 3% 手续费的分位四舍五入、净额为零与负调整结转。时间样本覆盖 UTC/北京时间跨日、支付第 29:59 与 30:00、售后窗口最后一秒及刚超时。测试时间可在测试配置中受控，生产接口不得提供任意改时间功能。

## 3 核心验收用例

下表均为待执行设计。实际报告必须填写版本、操作者、时间、观察结果与证据，不能直接复制“预期”作为“实际”。

| 编号 | 需求 | 前置和操作 | 预期结果与证据 |
|---|---|---|---|
| TC-01 | FR-01 | 注册会员，登录、刷新、退出，再用旧访问和刷新令牌 | 注册仅 MEMBER；刷新轮换；退出后两种旧令牌不可用；保存响应和脱敏会话证据 |
| TC-02 | FR-01/12 | 会员甲请求乙订单；商家 A 请求 B 的商品、订单、库存与结算 | 单资源 404，动作无权限 403；无数据泄露；列表严格按范围 |
| TC-03 | FR-01/12 | 禁用用户或移除其店铺成员资格后继续用原令牌写入 | 写请求立即被拒绝，授权变更留审计；不能仅等 JWT 自然过期 |
| TC-04 | FR-02/03 | 按 ISBN/书名/作者查书、排序分页；下架商品和停业店铺 | 搜索结果稳定；不可新购对象不再可下单；历史订单仍能读取快照 |
| TC-05 | FR-04 | 同 SKU 连续设置数量、地址切默认及删除 | 不重复生成购物车行、默认地址唯一；订单旧地址不变 |
| TC-06 | FR-05 | 会员选择 A/B 两店商品提交 | 一个批次两个订单；快照正确、库存同步预占；可独立支付取消 |
| TC-07 | FR-05/07 | A 有货 B 缺货或提交时变价；预览后修改地址或购物车数量 | 整批回滚，无孤立订单预占；变价返回 PRICE_CHANGED，地址/购物车变更返回 STATE_CONFLICT，均需重新预览确认 |
| TC-08 | FR-05 | 相同键相同参数提交 20 次，再同键改变 previewId | 只一个批次，相同结果；异参返回 IDEMPOTENCY_CONFLICT；订单金额和库存仅变一次 |
| TC-09 | FR-07 | 最后 10 本，100 个独立会员同时各买 1 本 | 最多 10 个预占成功，其余库存冲突；onHand≥reserved≥0；验 SQL 数据及日志，不只看 HTTP |
| TC-10 | FR-06 | 真实沙箱完成支付，重放成功通知 20 次 | 一次扣减、一次 PAID；核对渠道与本地单号金额，保留沙箱证据 |
| TC-11 | FR-06 | 伪造回跳 success 参数、错误签名、错金额通知 | 页面不能改状态；交易不变；错误记录脱敏，必要时生成差异 |
| TC-12 | FR-06/07 | 取消与支付成功并发；关闭响应丢失；查询超时 | 已付收敛 PAID，确认关闭才 CANCELLED；未知保持 CLOSING 和预占，无超卖 |
| TC-13 | FR-06/07 | 渠道请求已受理后进程崩溃并恢复 | 使用原 paymentNo 查单，不另建付款；状态最终收敛，无重复扣减 |
| TC-14 | FR-07 | 管理员尝试模拟确认；沙箱/prod 模式访问 mock-confirm | 无对应会员权限不能操作；禁用模拟时路由不存在，即使手写请求也失败 |
| TC-15 | FR-08 | 本店发货并人工录入轨迹，会员确认收货，重复确认；之后退货 | 一个 shipment；shipment_item 固化发货时剩余量，之后退货不改变历史发货量；状态不回退；轨迹标明人工录入 |
| TC-16 | FR-09 | 已支付未发货申请一部分退款，重复申请及超额申请 | 同行只一个进行中；可退数量被占用；越界拒绝，商家不能发货 |
| TC-17 | FR-09 | 客服同意，财务执行退款，渠道超时后重试 | 复用原 refundNo；核实成功只回补一次、累计金额数量正确；失败不假完成 |
| TC-18 | FR-09 | 完成后退货，批准、寄回、验收可再售、退款 | 验收回补一次，退款成功不再回补；不可再售合格退货仍退款但不回补 |
| TC-19 | FR-09 | 退货不符被拒、批准后 7 天未寄回、已寄回长期待验收 | 前两者按规则结束并释放申请数量；已寄回不能自动拒绝，产生待处理提示 |
| TC-20 | FR-10 | 完成订单评价，重复评价、全退行评价、超 30 天评价 | 一行一评，其余拒绝；运营隐藏后公开不显示，审计仍保留 |
| TC-21 | FR-11 | 窗口结束且无差异订单生成结算；同店同日重复创建 | 每订单仅一份明细，账期唯一，净额和手续费符合分位规则 |
| TC-22 | FR-11 | 有进行中售后、退款或对账差异时结算；创建人自批 | 结算被阻止；职责分离生效；界面显示阻止原因 |
| TC-23 | FR-11 | 模拟出款重试、晚到退款差异、负调整超过本期应付 | 不重复凭证；原出款账单不改，调整经复核转下一期；不产生负出款 |
| TC-24 | FR-13 | 上传超大、伪扩展名、路径穿越文件；他人下载私有凭证 | 拒绝危险文件，私有资源鉴权；公开目录无法绕过接口读凭证 |
| TC-25 | NFR-03 | 富文本注入、排序 SQL 片段、跨站刷新和旧刷新令牌重放 | 文本不执行、参数拒绝、CSRF 拒绝、会话族撤销；保存可复现请求 |
| TC-26 | NFR-02/05 | Outbox 发布确认丢失、消费者提交前崩溃、重复和乱序消息 | 消息可重送，业务副作用只一次；死信可定位重放；不依赖到达顺序 |
| TC-27 | NFR-05 | Redis 不可用、MQ 不可用、支付渠道故障 | 缓存受控回源或拒绝高风险请求，Outbox 不丢，熔断后可恢复；展示真实降级 |
| TC-28 | NFR-04/07 | 新环境部署，重启容器，再从备份恢复至隔离环境 | 数据持久，版本可核对，RPO/RTO 实测达标；文件引用和交易账一致 |
| TC-29 | NFR-01 | 按固定数据集和混合负载压测 | 附原始输出及看板，P95 与错误率达到目标；不包含第三方耗时或另行报表 |
| TC-30 | NFR-08 | 连续 24 小时每分钟探测就绪和读接口 | 记录全部探测、维护窗口和成功率；不能拿单次健康检查当可用性证据 |
| TC-31 | 工程化 | 提交故意失败测试、泄露样本凭据，部署坏镜像并回滚 | CI 拦截、镜像未发布/环境未晋级；恢复上一版本；证据不含真实秘密 |
| TC-32 | AI 留痕 | 抽查一个需求到代码、测试、PR 和 AI 对话 | 输入、模型版本、采纳理由、修改、验证与结果完整，无法取得的版本如实标注 |

## 4 性能测试口径

按 NFR-01 准备足够会员和 SKU，保证正常压测不因反复购买同一稀缺商品变成冲突测试。压测用户配置经记录后适当提高限流阈值；正常配置下另测 429。混合流量中下单只测内部创建，不自动等待沙箱付款；测试库有受控的订单清理/关闭策略避免无界预占，清理过程不得计入业务响应时长。

报告需列硬件、内核、容器资源限制、应用/JDK/数据库版本、提交 SHA、数据规模、连接池、是否命中缓存、预热、并发连接数和实际到达 RPS。预期业务冲突单独计数；意外 5xx、超时和网络错误计入错误率，不能从分母中随意剔除。样本不足时报告不具统计意义，不补造 P99。

## 5 验收执行顺序

先通过单元/契约，再做真实基础设施集成；先本地模拟再真实沙箱；先完整正常流程再并发异常；最后安全、性能和部署恢复。任一核心资金或库存一致性失败为阻断缺陷，即便页面可用也不能判整体通过。

报告分“通过、失败、阻塞、未执行”；阻塞项注明外部前置条件，例如沙箱权限或公网回调，不能并入通过。教师最终要求的测试报告由实际执行者填写 13 模板，本次提供计划而不是冒充测试完成。
