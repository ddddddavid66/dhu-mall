## 1 公共协议

业务前缀 `/api/v1`，JSON UTF-8，字段 lowerCamelCase。路径中的 id 均为内部 ID 的十进制字符串，orderNo 等业务单号仅用于展示和查询。时间为 ISO 8601 UTC，金额为两位小数字符串，数量为整数。不能向浏览器发送可能超出 JavaScript 安全范围的数值型 ID。

成功 Result 字段：code 固定为字符串 OK；message 为中文说明；data 为本操作返回模型；traceId 为本次请求跟踪号。失败 Result：code 为下表错误码；message 为用户可理解说明；data 为空；details 为可选的字段错误列表（field、reason）；traceId 必填。成功 GET/修改返回 200，新建资源返回 201，异步受理返回 202；不采用“所有失败也返回 HTTP 200”。

分页请求 page 默认 1、pageSize 默认 20 最大 100；响应 Page<T> 包含 items、page、pageSize、total。sort 为接口公布的枚举值，不接受数据库字段表达式。列表采用稳定的 id 次级排序。日期筛选为 UTC 起点包含、终点不包含。不存在或无权访问的个人/店铺单资源统一返回 404，动作权限不足返回 403。

除注册登录及公共读外使用 Authorization Bearer。刷新/退出使用刷新 Cookie 与 CSRF Header；令牌轮换规则见 02。接收合法 X-Request-Id 并限制长度字符集，否则生成 traceId；不可将客户端 traceId 当可信身份。

标记 **K** 的操作必须提供 Idempotency-Key（UUID 或等强随机字符串，最长 64）。标记 **V** 的修改携带 version 并检查乐观锁。未标记 K 不要求通用幂等，但 PUT/DELETE 自身状态设计为可重复。只有 02 指定的内部重试可自动重发关键写请求。

### 错误映射

| HTTP | code | 处理与适用范围 |
|---|---|---|
| 400 | PARAM_INVALID | 格式、数量、长度、排序或字段不合法 |
| 401 | AUTH_REQUIRED / TOKEN_EXPIRED | 重新登录或执行一次刷新；刷新失败清空会话 |
| 403 | ACCESS_DENIED / ACCOUNT_DISABLED / CSRF_INVALID | 无动作权限、账号禁用或跨站校验不通过 |
| 404 | RESOURCE_NOT_FOUND | 不存在或不属于当前数据范围 |
| 409 | STATE_CONFLICT / VERSION_CONFLICT | 状态或版本已变化，重新获取资源 |
| 409 | OUT_OF_STOCK / PRODUCT_UNAVAILABLE / PRICE_CHANGED | 重新确认购买内容，不能自动提交涨价订单 |
| 409 | IDEMPOTENCY_CONFLICT / REQUEST_IN_PROGRESS / IDEMPOTENCY_KEY_EXPIRED | 同键异参、原请求处理中或重放窗口已结束 |
| 409 | REFUND_LIMIT_EXCEEDED / SETTLEMENT_BLOCKED | 可退数量金额不足或结算资格不满足 |
| 410 | PREVIEW_EXPIRED | 重新预览；已用预览以 STATE_CONFLICT 处理 |
| 413 / 415 | FILE_TOO_LARGE / FILE_TYPE_UNSUPPORTED | 上传大小或格式不支持 |
| 429 | RATE_LIMITED | 携带 Retry-After 秒数，界面倒计时，不无限重试 |
| 502 / 503 | CHANNEL_UNAVAILABLE / DEPENDENCY_UNAVAILABLE | 不宣称支付或退款失败终结，展示处理中并查询 |
| 500 | INTERNAL_ERROR | 通用说明及 traceId，内部异常仅入脱敏日志 |

## 4 接口内部处理设计

| 场景 | 处理顺序与事务边界 | 主要错误 |
|---|---|---|
| API-27 下单 | 验证登录与 K → 锁预览 → 校验归属、时间、价格版本 → 按序锁库存 → 创建全部订单及预占 → 快照与 Outbox → 提交 → 返回 BatchView | PREVIEW_EXPIRED、PRICE_CHANGED、OUT_OF_STOCK；任一店铺失败则整批不建立 |
| API-32 支付 | 核对本人订单与待付款状态 → 复用或创建唯一支付 → 事务外渠道调用 → 保存渠道受理结果 | STATE_CONFLICT、CHANNEL_UNAVAILABLE；超时不得另建付款号 |
| API-35 回调 | 协议验签及参数核对 → 去重 → 锁订单和支付 → 变更库存与订单 → 同事务日志事件 → 回应渠道 | 无签名、金额不符、未知单号不改变交易；异常登记差异 |
| API-40 发货 | 本店与角色校验 → 锁订单 → 无待售后且有剩余量 → 唯一 shipment → 状态变化和审计 | ACCESS_DENIED、STATE_CONFLICT、VERSION_CONFLICT |
| API-42 售后 | 本人 → 锁订单行 → 校验时间、类型、剩余数量 → 检查凭证归属 → 创建申请 | REFUND_LIMIT_EXCEEDED、STATE_CONFLICT |
| API-53 退款 | 校验职责分离 → 核对批准和验收 → 复用原退款单 → 事务外渠道调用 → 查询收敛 → 事务记账回补 | STATE_CONFLICT、CHANNEL_UNAVAILABLE；未知结果不能判退款完成 |
| API-59/60/61 结算 | 锁账期及订单 → 校验无售后/差异 → 冻结快照 → 独立审核 → 出款前重验 → 模拟凭证及审计 | SETTLEMENT_BLOCKED、VERSION_CONFLICT；不可将模拟当真实银行结算 |

## 5 契约交付要求

后续实现模型根据本文件生成 OpenAPI 3.1；每操作有请求、响应、权限、错误示例及 operationId。第三方通知、multipart 和二进制响应单独描述，不能标成统一 JSON。正常、参数错、未登录、越权、状态冲突至少各一项契约断言；关键写接口另测重放及同键异参。

新增接口必须先更新本目录和模型，禁止为前端临时增加“万能更新订单状态”或“任意退款金额”接口。前端 Mock 只模拟本契约，不能为页面方便另造与后端不同的字段。

## 6 阶段 A 技术占位补充

2026-10-23 阶段 A 初始化：92 项业务操作只建立清单与 OpenAPI 骨架，未实现操作统一返回 HTTP 501、code=NOT_IMPLEMENTED；API-34 模拟确认入口不启用，返回 404。已知路径的不支持方法返回 HTTP 405、code=METHOD_NOT_ALLOWED。这两项是工程阶段的技术错误，不改变原有业务成功、权限或资金规则。

占位接口不提供 2xx 响应，不执行业务 DTO、JWT/RBAC 或渠道验签；API-35 的占位 JSON 501 也不是正式支付宝通知应答，后续接入必须切换为本文件原定渠道协议。待业务实施时，逐项补齐请求/响应 schema、安全和实际状态码，再更新 x-implementation-status，不能因为存在契约就宣称业务完成。

阶段 E 实施注记（2026-10-25）：API-32—35 已有适配与协议实现；OpenAPI 0.5.0 共 56 项实现，模拟确认运行时受环境限制。refund.reason_type 长度冲突已按用户决策由 V9 扩至 32 字符并同步函数唯一索引；真实沙箱未联调，因此阶段未全通过；不得用实现标记替代验收结果。
